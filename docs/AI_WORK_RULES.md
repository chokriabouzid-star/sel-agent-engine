# قواعد العمل مع نماذج الذكاء الاصطناعي — SEL Agent Engine

## القاعدة 0: لا يبدأ النموذج بالتنفيذ أبدًا قبل القراءة
أي نموذج يقترح تعديل كود **قبل** أن يقرأ الملفات المعنية = **أوقفه فورًا**.
النموذج لا يعرف مشروعك. هو يخمّن. والتخمين يكسر.

## القاعدة 1: كل جلسة تبدأ بالسياق
الصق هذا البرومبت في بداية **كل محادثة جديدة** (انظر ملف SESSION_PROMPT.md).

## القاعدة 2: لا تعديل بدون تشخيص
### الترتيب الإلزامي:
1. **اقرأ** — أعطِ النموذج الملفات المعنية فقط
2. **شخّص** — اطلب منه تحديد السبب الجذري بالسطر
3. **اقترح** — اطلب الحل بدون تنفيذ
4. **راجع** — اقرأ الحل وتأكد أنه منطقي
5. **نفّذ** — طبّق التعديل
6. **تحقق** — شغّل أوامر التحقق

## القاعدة 3: لا تعديل واسع
- تغيير ملف واحد في كل خطوة
- `cargo check` بعد كل تعديل
- `cargo test` بعد كل تعديلين
- `regression_gate.sh core` قبل أي commit

## القاعدة 4: لا تثق بالنموذج الذي يقول "أعرف مشروعك"
### علامات الخطر:
- يقترح حلولًا بدون قراءة الكود
- يعدّل ملفات لم تطلب تعديلها
- يقول "هذا بسيط" لمشكلة لم يشخّصها
- يقترح `git reset --hard` بدون شرح ما سيُفقد
- يكتب كودًا طويلًا دون اختبار تدريجي

### ماذا تفعل:
قل له: **"توقف. أعطني أوامر قراءة فقط أولًا."**

## القاعدة 5: وثّق قبل أن تنتهي الجلسة
قبل إغلاق أي محادثة:
1. اطلب من النموذج تلخيص ما تم
2. احفظ التلخيص في `docs/sessions/`
3. حدّث `STABILITY_LEDGER.md`

## القاعدة 6: فصل أنواع العمل
لا تخلط في جلسة واحدة:
- إصلاح محرك (engine fix)
- إصلاح fixture/trajectory
- إضافة ميزة جديدة
- تنظيف/refactor

كل نوع = جلسة منفصلة بهدف واحد.

## القاعدة 7: الشجرة النظيفة مقدسة
- `git status --short` يجب أن يكون فارغًا قبل وبعد كل جلسة
- أي ملف متسخ يجب إما commit أو restore قبل أي عمل جديد
