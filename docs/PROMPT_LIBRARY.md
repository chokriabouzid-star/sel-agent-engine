🚀 P-01: بروبت فتح الجلسة الكامل
text

أنا أعمل على مشروع Rust اسمه sel-agent-engine.
هو وكيل ذكي يحل مهام برمجية تلقائيًا.

## البنية الأساسية:
src/
  agent.rs           — حلقة التنفيذ الرئيسية
  protocol.rs        — parser لردود LLM إلى أوامر Cmd
  state_handlers.rs  — إدارة الحالات Planning/Executing/Repairing
  executor/
    core.rs          — تنفيذ shell/write/patch
    runner.rs        — تنفيذ run_tests لكل لغة
    run_policy.rs    — سياسات preflight
  llm/
    replay.rs        — replay trajectories
    record.rs        — تسجيل trajectories
  scaffold_engine.rs — تجهيز بيئة العمل
  snapshot.rs        — git stash/restore
  bench_sel.rs       — بنشمارك SEL v1.1
  bench_swe.rs       — بنشمارك SWE
scripts/
  regression_gate.sh — يجب أن يمر قبل أي commit

## معايير الاستقرار:
cargo fmt --check
cargo check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
scripts/regression_gate.sh core

## قواعد العمل معي:
1. لا تعدّل كودًا قبل أن تقرأ الملفات المعنية
2. أعطني أوامر قراءة أولًا، ثم شخّص، ثم اقترح
3. تغيير واحد ثم تحقق، لا تعديل واسع
4. لا git reset --hard بدون تحليل ما سيُفقد
5. لا تفترض أنك تعرف محتوى أي ملف

🔍 P-02: طلب التشخيص فقط
text

الآن شخّص السبب الجذري فقط بناءً على ما قرأته.

أريد:
1. السبب الجذري بجملة واحدة
2. الدليل من الكود: الملف والسطر
3. لماذا هذا هو الجذر وليس عرضًا جانبيًا؟
4. ما الذي لا تعرفه بعد وتحتاج قراءته؟

لا تقترح حلًا بعد.
🎯 P-03: طلب خطة التعديل
text

اقترح خطة التعديل الآن.

أريد:
1. أصغر تعديل ممكن يعالج السبب الجذري فقط
2. الملفات التي ستتغير (ملف أو ملفان كحد أقصى)
3. الملفات التي لن تتغير
4. أوامر التحقق بعد التعديل
5. النتيجة المتوقعة

لا تكتب الكود بعد. فقط الخطة.
⚡ P-04: طلب التنفيذ
text

نفّذ التغيير الأول فقط من الخطة.
أعطني:
- الكود الكامل للتعديل
- أمر التحقق الفوري

لا تنتقل للتغيير الثاني إلا بعد أن أرسل لك نتيجة التحقق.
🛑 P-05: إيقاف النموذج عند القفز للتنفيذ
text

توقف.
أنت تقترح تعديلات قبل التشخيص الكافي.
أريد منك أولاً:
- قراءة الملفات المعنية
- تحديد السبب الجذري بدليل
لا تكتب كودًا حتى أطلب ذلك.
📊 P-06: عزل regression جديد
text

ظهر فشل جديد. قبل أي شيء:

1. ما نوع هذا الفشل؟
   - engine bug
   - fixture/trajectory قديم
   - solver quality
   - environment issue
   - test mismatch

2. كيف نعيد إنتاجه؟ أعطني أمرًا واحدًا.

3. هل هذا موجود في STABILITY_LEDGER؟

لا تقترح إصلاحًا بعد. فقط التصنيف وإعادة الإنتاج.

🚨 P-08: حالة طوارئ — شجرة متسخة بدون خطة
text

توقف تمامًا عن أي اقتراح.
شغّل هذا أولاً وأرسل لي النتيجة:

git status --short
git stash list
git log --oneline -5

لا تقترح git reset أو git clean أو أي أمر خطر.
سننظر في المخرجات أولاً.
🔬 P-09: مراجعة patch قبل التطبيق
text

قبل أن أطبق هذا التعديل، أريد:

1. هل هذا التعديل يمس ملفات غير معلنة في الخطة؟
2. هل هناك اختبارات موجودة لهذا الكود؟
3. هل الاختبارات الحالية ستكسر؟
4. ما أوامر التحقق الكاملة؟

أجب على هذه الأسئلة الأربعة قبل أي شيء.

قراءة مطلوبة:

لا تمس:

- أي ملفات src خارج نطاق هذه الحالة

ابدأ بقراءة الـ trajectory الحالي.
